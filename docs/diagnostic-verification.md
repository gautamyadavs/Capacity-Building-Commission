## Mayer audit findings and implementation

Mayer’s coherence and signaling principles are applied here as a local design inference for a predominantly text-based diagnostic. Changes remove competing interface material and improve access to relevant facts; completion speed is not evidence of learning gain.

| Observed issue                               | Implemented repair                                                                                           | Verification                                                                                                                       |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| Lengthy home instructions and version labels | Short orientation, suggested start, optional full instructions and design/source details                     | Revised home inspected; all assistance, supplied-fact authority, formats, pause/resume, locking and review conditions stay visible |
| Facts far above initial writing fields       | Facts and form paired at widths ≥1100 px; mobile briefing and sticky reference control                       | A1 first initial field is approximately 739 px from the top at 1365 × 900, versus 1,222 px in the deployed audit                   |
| Expanded history before update fields        | Default new-information pane; separate initial-facts and exact submitted-response references                 | A1 first update field is approximately 713 px from the top, versus 2,357 px; exact prior response observed                         |
| Quantities buried in paragraphs              | Nine neutral accessible tables with qualifications alongside values                                          | Source readback, native PDF layout, all eight case phases and reveal guards checked                                                |
| Technical prompt/action wording              | Plain labels; explicit initial/update submit actions and read-only consequence                               | Native confirmation dialogs, cancellation, repeated submission and record IDs verified                                             |
| Reviewer link mixed into learner navigation  | Reviewer workspace in footer; submissions/feedback link for ended runs                                       | Learner, reviewer and imported feedback paths verified                                                                             |
| Suggested order actually enforced            | Free case order for new runs, independent drafts, latest-activity resume and direct return to case selection | B2/A2/B1/A1 start order; A2/B1/A1/B2 completion; refresh and phase boundaries verified                                             |
| Repeated pending status across 20 profiles   | One review summary and compact expandable case records                                                       | One “Awaiting review” occurrence; four case records initially collapsed; partial/uncertain feedback and history verified           |
| Recovery actions compete with storage detail | Back up / Restore / Start again; advanced storage help                                                       | Save failure and retry, exported drafts, cancelled replacement, import/archive and malformed storage recovery verified             |

All current-phase questions remain visible in the response form. Desktop facts have their own keyboard-focusable scroll region; mobile reference dialogs restore focus and writing position when closed. Table result columns remain unavailable until that case’s initial response is submitted. Captured paragraph facts remain for backward compatibility. The definitions of PM2.5 and administrative grievance closure are preserved.

Feedback leads with criterion meaning, exact response evidence, rationale, supported strength/gap or limitation and the next opportunity. Record metadata, descriptor references and superseded judgements remain in details. Blank/missing evidence and uncertain review status are distinguished from performance levels. Reviewer-only illustrations and calibration guidance are gated by captured source-version matching and are not automatic learner feedback.

The interface contains no decorative imagery, sound, animation, motivational quote, case-specific coaching, additional answer requirement, timer or automatic score. Narration-specific redundancy, modality, temporal contiguity, voice and presenter-image principles have no current media to assess. Optional practice remains deferred.

## Captured configuration and compatibility

`caseOrderPolicy` is optional (`fixed` or `free`); absence retains the previous fixed A1/A2/B1/B2 progression. `briefingBlocks` is optional and supports neutral paragraphs/headings and rectangular factual tables; absence renders the captured paragraph facts. New sessions capture KALP-ALIGN-05. Existing runs retain their complete original content, phase versions, policy and review binding. Arbitrary-order validation checks unique actual starts, chronological and complete submission records, and each case’s initial-before-update reveal boundary. Hash routes, the Pages subpath and schema version 3 are retained.

The original KALP-ALIGN-04 fixture verifies backward compatibility; it is not the content-authoring source. Journal, cross-tab, archive and recovery behaviour remains in the existing persistence layer. All observations and review records used in testing are explicitly synthetic software fixtures.
